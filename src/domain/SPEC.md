## Responsibility

Owns all pure, deterministic business logic for Lease Loop. Every calculation, rule evaluation, and state-transition decision is expressed here as a plain function with a co-located Vitest suite (`*.test.ts`).

- **Implemented rules:**
  - `coefficient.ts` (`monthlyFactorFor`): Resolves the financing band (`A`–`D`, inclusive cent bounds) and monthly factor for a financed cent amount and term (`12`, `24`, `36`, `48` months), returning `{ ok: false, reason: 'below_minimum' | 'above_maximum' | 'unknown_term' }` when out of bounds.
  - `price-list.ts` (`listPriceOn`): Resolves an asset's net list price and price-list version on a given `YYYY-MM-DD` date (`valid_from <= isoDate` and `valid_to === null || isoDate <= valid_to`).
  - `contract-pricing.ts` (`calculateContractQuote`, `vatRateOn`, `downPaymentBoundsFor`, `clampDownPaymentCents`, `availableTermsFromTable`): Quote from list price, term and down payment (monthly net rent, VAT, buyout, totals) and VAT lookup by date. Moves into `pricing/` and switches to integer rates (see rounding rule below).
  - `money.ts` (`formatEuro`): Formats integer euro cents into localized currency strings at the UI edge.
  - `question-flow.ts`: `evaluateCondition` / `isAskable` evaluate `ask_when` (all conditions must hold; `in` compares as text, `gte`/`lte` are inclusive and numeric only; an unknown value never satisfies a condition). `visibleQuestions` returns the applicable questions in bank order and ignores the stored answer of any question that is itself hidden. `pruneAnswers` returns `{ kept, dropped }` after an earlier answer or the deal changes; cascades resolve in one pass and answers for unknown ids are dropped too.
  - `business-id.ts` (`isValidBusinessId`): Finnish Y-tunnus format and check digit (weights 7, 9, 10, 5, 8, 4, 2; remainder 1 is never valid).
  - `eligibility.ts` (`decideEligibility`, `ageOn`): turns answers into `yes`, `no`, `manual_review` or `incomplete` (with the missing question ids). Reasons are `{ rule, outcome, params }`, never prose, so the UI translates them. A hard `no` wins immediately, even while other questions are unanswered; then `incomplete`; then `manual_review`. Rules: `min_age` (on the contract start date), `residency`, `affordability` (rent incl. VAT × 100 > income × 30, integers only; skipped when the caller passes no rent or the income question was not asked), `business_id`, `pep_manual_review`, `financed_limits`. Two ids go beyond the data pack: `signatory_required` (applicant cannot sign for a company: manual review) and `blocked_answer` (any `answer_in` block other than the country). Income answers are whole cents.
  - `invoice-schedule.ts` (`isLeapYear`, `daysInMonth`, `addMonthsClamped`, `formatInvoiceNumber`, `generateFinnishReferenceNumber`, `generateInvoiceSchedule`): Pure calendar date math with month-end clamping (`Jan 31` → `Feb 28` / `Feb 29` on leap years), deterministic invoice document ID and modulo-10 (weights 7, 3, 1) Finnish reference number generation, and monthly invoice generation that locks contract net rent while resolving VAT dynamically on each invoice's due date (`isVatChangedFromSigning`).
  - `end-of-term.ts` (`calculateBuyoutSettlement`, `interpolateResidualCurve`, `calculateResidualMarketValue`, `matchSecondLifeWaitingList`, `calculateAvoidedCo2`): Pure end-of-term logic covering buyout settlements with dynamic VAT on settlement date, residual curve interpolation with condition and usage adjustments (validated on Card 9), deterministic second-life waiting list matchmaking (by earliest needed_by and signup order), and circular avoided manufacturing CO₂ calculation.
  - `refurbishment.ts` (`fixedRefurbishmentFor`): Turns the `fixed` steps of `refurbishment-costs.json` from rules in words into costs: `always`, `usage.value >= <n> <unit>` and `per started <n> <unit> since last service` (counted from the use since the item was last ready to lease). Reports whether a step resets usage. Throws on an unknown rule or a unit mismatch, so a new rule cannot be skipped silently. Optional condition upgrades are not included.
  - `early-exit.ts` (`billedMonthsAsOf`, `outstandingBalanceCents`, `calculateEarlyExit`, `checkReturnInspection`, `worseCondition`): Fair early exit (Smart Problem 2, card 8), designed in `ARCHITECTURE.md` §7. The outstanding balance is the remaining rents plus the end-of-term buyout, each discounted at the band's monthly rate; with no rents left it equals the buyout exactly. The customer can buy it out (pay the balance) or return it (pay `max(0, min(balance − credit, remaining rents))`, where the credit is the market value from `calculateResidualMarketValue`, at an age of the rent periods started and the inspected condition and usage, minus `fixedRefurbishmentFor`, never below 0; a usage-resetting step values the item at 0 usage). `checkReturnInspection` refuses an inspected usage below the reading at the start of the lease, or a condition better than the recorded one. The present value is computed exactly as one BigInt fraction (the annual rate in whole basis points, so `1 + r = (120000 + bp) / 120000`) and rounded half up once; the "interest not charged" line is derived, so every option's `lines` add up to its net amount. VAT follows the exit date through `calculateBuyoutSettlement`. Throws `RangeError` for an exit date before the lease starts. `earlyExitForContract` prices an exit from a signed `ContractQuote`, an exit month (clamped to the term), the return inspection and the asset's record (its usage is the reading at the start of the lease); the invoices page and the early-exit route both use it.
- **Target Spine & Smart Problem engines (not yet implemented):**
  - `end-of-term`: Contract extension.
  - `second-life`: Mandatory/optional refurbishment cost evaluation (`refurbishment-costs.json`).

## Contracts and Decisions

- **Cent rounding rule:** Money is always an integer number of euro cents (`Number.isInteger(cents)`). Rates are integers, converted once at the data edge: VAT and interest in basis points (`25.5` → `2550`), coefficient factors in parts per million (`0.027584` → `27584`), buyout as a whole percent. Every derived amount is rounded once, half up, with integer arithmetic via `mulDivRound(a, num, den)`: rent = `mulDivRound(financed, factorPpm, 1_000_000)`, VAT = `mulDivRound(net, vatBp, 10_000)`, buyout = `mulDivRound(financed, percent, 100)`. This matches `data/DATA.md` (`10730`, `2736`, `13466`, `58350`). The present-value discount in `early-exit/` is an exact BigInt fraction, rounded half up once. Passing a non-integer cent value to a domain function is a programming bug and throws `RangeError`.
- **Expected failures are values, not exceptions:** Domain rejections (amount below minimum, unknown asset, ineligible applicant) return discriminated unions (`{ ok: true, ... } | { ok: false, reason }`). Exceptions (`RangeError`) are thrown only for contract violations by the caller (non-integer cents or malformed `YYYY-MM-DD` strings).

## Boundary

- **Allowed imports:** Types and pure schemas from `data` (`@/data/schemas`) and sibling modules inside `src/domain/`.
- **Forbidden reaches (enforced by `eslint.config.mjs`):** Must never import `node:*`, `@/data/load`, `@/server/*`, `@/app/*`, `@prisma/*`, `@/generated/*`, `next/*`, or `react`, and must never access `fetch`, `process`, ` console`, `Date.now()`, `new Date()`, or `Math.random()`. All dates arrive as `YYYY-MM-DD` arguments from the caller.
